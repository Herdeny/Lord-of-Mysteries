# M3 旅行家持续双向远门

> 适用版本：0.9.25-1.20.1
> 状态：`code_ready`
> 设计基线：v0.9 旅行家序列 5“远门”纵切；仓库既有行为优先

## 1. 玩家目标

旅行家序列 5 可以把原版磁石指南针作为跨重启空间标记。手持有效标记按 `U` 后，
服务器在旅行家附近与目标磁石处生成一对持续 20 秒的真实双向门。玩家主动走入门体才会
传送；开门不会强制移动旅行家或附近玩家。

如果双手都没有指南针，`U` 保留原有“返回雾都前哨”兼容路线。只要任一只手拿着指南针，
能力就严格走磁石标记校验；未绑定、损坏或失效的指南针不会回退到出生点或前哨，也不会扣费。

## 2. 快速使用

1. 在原版磁石上使用指南针，生成带 `LodestonePos` 与 `LodestoneDimension` 的标记。
2. 输入 `/pm travel` 检查目标维度、坐标、磁石状态、门持续时间与当前访问权限。
3. 可选：输入 `/pm travel access private|party|public` 设置之后开启的门。
4. 旅行家手持有效标记按 `U`。
5. 等待两端门体出现；源门位于旅行家前方安全地面，目标门位于磁石上方。
6. 需要通行的玩家主动走入任一门体。抵达后获得 3 秒抗性 II，并有 2 秒反回弹冷却。

同一门主同时只保留最新一对门。再次成功开门会清除之前仍存在的端点，避免无限实体堆积。

## 3. 费用、寿命与冷却

| 项目 | 数值 |
|---|---:|
| 基础开门消耗 | 80 灵性 |
| 开门同行支持者 | +10 灵性/人 |
| 支持者上限 | 3 人 |
| 支持识别半径 | 4 格 |
| 双向门寿命 | 400 tick / 20 秒 |
| 主持者再次开门冷却 | 36,000 tick / 1,800 秒 |
| 非门主再次作为开门支持者的冷却 | 1,200 tick / 60 秒 |
| 单次穿门反回弹冷却 | 40 tick / 2 秒 |
| 抵达保护 | 60 tick / 3 秒抗性 II |

开门支持者必须与主持者同维度、存活、非旁观、非睡眠、主动潜行、位于四格内、手持完全相同
的磁石标记且不在搭乘冷却。支持者只影响开门费用和邀请提示，不会被强制传送。

## 4. 两层明确同意

本实现把多人同意拆成两层，避免“站得近就被传走”：

1. **开门支持同意**：潜行、四格内、持相同标记，用于计算 `80 + 10 × 支持者`。
2. **最终通行同意**：玩家本人走入门体，才会触发权限检查和传送。

未潜行、拿错标记或不在四格内的玩家不会计入费用，但只要门权限允许，他们仍可在 20 秒内
自行走入门。反之，即使某玩家在开门时被计为支持者，不进入门体也不会移动。

## 5. 访问权限

| 模式 | 命令 | 可通行者 |
|---|---|---|
| 私人 | `/pm travel access private` | 仅门主 |
| 队伍（默认） | `/pm travel access party` | 门主，以及开门时与门主同一原版记分板队伍的玩家 |
| 公开 | `/pm travel access public` | 任意存活、非旁观玩家 |

门主在所有模式下始终可用。队伍名称与权限在开门时写入门实体快照；门存在期间改队或改权限
不会追溯修改已经生成的门。非法、空或旧档缺失的权限值由 schema 25 修复为 `party`。

这里的“队伍”指原版 `/team` 记分板队伍，不读取客户端自报成员，也不允许一名玩家替另一名玩家
确认。外人触碰私人或队伍门只收到限频拒绝提示，位置、灵性和冷却保持不变。

## 6. 服务端安全顺序

开门全部由服务端执行，顺序固定为：

1. 验证旅行家序列、技能冷却和双手指南针 NBT。
2. 验证目标维度存在，目标坐标处于世界高度与 World Border 内。
3. 在加载区块后验证目标方块仍是物理磁石。
4. 为源端寻找坚实地面与两格无碰撞空间；验证目标端门体空间。
5. 预演源端与目标端的安全抵达位置，并拒绝过近标记。
6. 收集最多三名开门支持者并计算精确费用。
7. 扣除灵性，依次生成源端和目标端实体。
8. 两端都成功后才清除旧门并开始 1,800 秒主持冷却；任一端失败会移除已生成端点并退款。

玩家穿门时会再次验证目标维度、World Border、区块、坚实地面与实体碰撞。目标失效时玩家留在
原地，不写入穿门冷却，也不会被传到出生点。

## 7. 持久化与迁移

Capability schema 25 新增 `traveler_door_access_mode`，默认 `party`。复制、死亡重生、序列化、
Provider 往返和旧档 DataFix 均保留或修复该值。

每个 `traveler_door` 实体保存：

- `owner`：门主 UUID，用于权限与单门主单对门约束；
- `owner_team`：开门时的原版记分板队伍名快照；
- `access_mode`：`private`、`party` 或 `public`；
- `target_dimension`：另一端维度；
- `target_anchor`：另一端磁石或源门地面锚点；
- `remaining_ticks`：最多 400 tick 的剩余寿命。

门实体重启后只在仍有剩余寿命且字段合法时恢复。非法维度、缺失门主、非正寿命或损坏字段不会
构成可用门。乘客开门支持冷却写入服务端玩家持久数据；40 tick 反回弹冷却只承担短时防循环职责。

## 8. 失败与恢复矩阵

| 场景 | 结果 |
|---|---|
| 未绑定指南针 | 拒绝；不扣灵性、不冷却 |
| 目标维度不可用 | 拒绝；不加载伪造维度 |
| 坐标越界或超出 World Border | 区块加载前拒绝 |
| 物理磁石被移除 | 标记失效；不回退出生点 |
| 源门无坚实地面或门体空间被占用 | 拒绝；不扣费 |
| 目标端无安全抵达位置 | 拒绝；不扣费 |
| 标记离源门过近 | 拒绝；避免重叠和循环 |
| 灵性不足 | 拒绝；不生成任一端 |
| 第一端生成失败 | 退款；不开始冷却 |
| 第二端生成失败 | 清除第一端并退款 |
| 外人触碰私人/队伍门 | 原地拒绝；限频提示 |
| 穿门后立即碰到目标端 | 40 tick 冷却阻止回弹 |
| 门存在期间目标变得不安全 | 玩家留在原地；门仍按寿命自然消失 |
| 重复成功开门 | 清除同门主旧端点，只保留最新一对 |

指南针与磁石始终不会被开门或穿门消耗。

## 9. 自动化验证

当前发布门禁包含 384 项 JUnit 与 15 项 Forge GameTest：

- `M3TravelNetworkLogicTest`：费用钳制、支持者资格、20 秒寿命与反回弹常量；
- `TravelerDoorAccessModeTest`：门主优先、私人/队伍/公开、队伍规范化和非法值回退；
- `PlayerMysteryDataTest` / `PlayerMysteryDataFixerTest`：schema 24→25、复制、NBT 往返与坏值修复；
- 第 11 项 GameTest：真实磁石、源/目标门、精确扣费、未强制移动、20 秒寿命、开门冷却和失败保留；
- 第 15 项 GameTest：外人拒绝、原版队友通过、跨门安全落点、目标端防回弹及门 NBT 往返；
- 同一持久测试世界连续运行会使用本轮唯一特性来源，确保全服来源账本不会让复跑测试产生假失败。

CI 另外执行 M3 机器合同、资源/翻译/Pages 图鉴门禁、clean build、存档回滚和同一世界双启动专服矩阵。
