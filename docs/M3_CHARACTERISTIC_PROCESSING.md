# M3 非凡特性处理工作台

> 适用版本：0.9.22-1.20.1 · 设计基线：v0.9 · 状态：`code_ready`

0.9.22 实现 v0.9 第 63 章的首个可玩纵切：玩家可以在生存模式中检查、拆分、重组、封存和洗涤带有完整 `CharacteristicBundle` 的破碎特性。处理由服务端执行，失败不会扣除特性、催化剂或探针耐久。

## 可制作内容

| 注册 ID | 配方要点 | 用途 |
|---|---|---|
| `lord_of_mysteries:characteristic_separator` | 紫水晶碎片、占卜水晶、铁锭、黑曜石 | 检查、拆分、重组、封存与解封 |
| `lord_of_mysteries:imprint_washing_altar` | 紫水晶碎片、月华水、灵性盐、磨制深板岩、深板岩 | 洗涤污染与精神烙印 |
| `lord_of_mysteries:imprint_probe` | 紫水晶碎片、占卜水晶、铁锭 | 检查、拆分与解封；64 耐久 |
| `lord_of_mysteries:memory_seal_wax` | 蜜脾、纸、灵性盐 | 一次制作 4 个；封存一份特性 |
| `lord_of_mysteries:imprint_washing_incense` | 安神熏香、灵性盐、灰烬粉、月华水 | 每次成功洗涤消耗 1 个 |

所有配方只使用当前版本已可获取的原版或 Mod 物品。两种工作台均有方块模型、物品模型、掉落表和双语名称。

## 分离台操作

主手必须持有带有效特性载荷的物品；副手决定操作：

| 副手与动作 | 结果 |
|---|---|
| 烙印探针，普通右键 | 显示最高序列、守恒单位、平均纯度、污染、烙印、洗涤次数、来源摘要和封存状态 |
| 烙印探针，潜行右键 | 未封存时拆出最高序列层的 1 个单位；已封存时解除封存 |
| 另一份有效特性，右键 | 重组两份不同来源的同途径特性 |
| 记忆封蜡，右键 | 封存特性；封存期间禁止拆分、重组和洗涤 |

拆分成功后，主手保留析出的最高序列单位，剩余载荷优先放入背包；背包已满时只把剩余载荷安全掉落在玩家脚边。重组成功后主手获得结果，副手第二份特性被精确移除。

## 洗涤台操作

主手持未封存的有效特性，副手持烙印洗涤香后右键：

- 污染降低 25 点，最低为 0；
- 烙印支配度降低 20 个百分点，最低为 0；
- 每一层纯度永久降低 3 个百分点，最低为 10%；
- 洗涤次数增加 1，来源哈希派生为新的可审计值；
- 已完全无污染且无活跃烙印的特性会拒绝洗涤，不消耗熏香。

洗涤是风险换恢复，不是免费清除。永久纯度损失会保留在后续拆分和重组结果中。

## 守恒与重组规则

- 拆分前后的总单位数必须相等；只允许总单位数大于 1 的载荷继续拆分。
- 仅同途径特性可以重组，不同途径会原样退回。
- 两份来源哈希完全相同的载荷会被拒绝，防止直接复制后回灌。
- 每个序列层最多保存 64 个单位，超过上限的重组会被拒绝。
- 相同序列层按单位数计算加权平均纯度。
- 重组后的污染为双方按单位数加权平均再增加 5 点。
- 烙印按单位数合并，支配度在加权平均后增加 5 个百分点；低序列号的已知前任序列优先保留，低语池稳定去重并限制为 16 条。
- 拆分、重组和洗涤都会生成确定性的 SHA-256 派生来源哈希，方便日志和后续审计。

同源拒绝只阻止“完全相同来源哈希”的直接重组，不等同于服务器级全局防复制账本。服主仍应使用正常的存档、权限和反作弊措施。

## 失败恢复矩阵

| 条件 | 服务端结果 | 资源结果 |
|---|---|---|
| 主手没有有效载荷 | 拒绝 | 全部保持不变 |
| 最后一个守恒单位继续拆分 | 拒绝 | 探针不掉耐久 |
| 不同途径重组 | 拒绝 | 主副手均保持不变 |
| 相同来源哈希重组 | 拒绝 | 主副手均保持不变 |
| 单层重组后超过 64 | 拒绝 | 主副手均保持不变 |
| 已封存时拆分、重组或洗涤 | 拒绝 | 催化剂和载荷保持不变 |
| 重复封存或解封未封存特性 | 拒绝 | 封蜡或探针不消耗 |
| 已完全洁净时洗涤 | 拒绝 | 洗涤香不消耗 |
| 拆分时背包已满 | 操作成功 | 剩余特性掉落在操作者脚边，不会静默删除 |

工作台仅处理玩家真实双手物品，没有客户端自报数值、远程方块调用或玩家 UUID 共享状态；因此两名玩家可并行使用不同工作台，结果仍按各自物品与服务端交互顺序结算。

## 引导与验收

- `/pm characteristic`：显示两种工作台、催化剂、数值代价和失败安全规则。
- 破碎特性悬停文本：直接显示守恒单位、平均纯度、污染、烙印、洗涤次数与封存状态。
- JUnit：8 项逻辑测试覆盖拆分守恒、单单位拒绝、加权重组、同源拒绝、途径不匹配、交换顺序确定性和洗涤代价。
- Forge GameTest：第 12 项真实服务器测试放置两种注册方块，验证封存、失败回滚、拆分/重组守恒、净化代价、操作审计和物品 NBT 往返。
- 专服：注册、配方、资源与 NBT 在同一世界双启动矩阵中加载。

本纵切没有实现从活体玩家额外负荷中自动提取特性、跨服务器全局来源账本、组织级加工服务、跨途径高阶聚合或最终原创工作台美术；这些内容不能标记为已完成。
