# M3 秘偶大师持久编队

> 适用版本：0.9.31-1.20.1
> 状态：`code_ready` 可玩纵切
> 设计基线：v0.9 秘偶大师序列 5；仓库现有服务端规则优先

## 1. 玩家目标

占卜家途径晋升至序列 5 秘偶大师后，可以把濒死的普通敌对生物转化为持久秘偶。秘偶 UUID
保存在玩家 Capability，所有权同时写入实体持久数据，因此死亡重生、重登和服务器重启后仍能识别。

当前纵切提供三人编队、跟随/守卫/被动三种持久战术、离线 NoAI 休眠、安全召回、主动解除、玩家友军保护、主人绑定收纳卷轴和跨维安全部署。完整原典能力组、世界级离线名单对账、复杂阵型和更细粒度目标优先级仍在后续门禁。

## 2. 创建条件

1. 玩家必须是占卜家途径序列 5。
2. 对准 14 格内敌对生物，按住潜行再按 `U`。
3. 目标必须存活、最大生命不高于 80，且当前生命不高于最大生命的 20%。
4. 玩家编队少于 3 个槽位，目标不能已经属于自己或其他玩家。
5. 创建消耗 60 灵性，并写入 2,400 tick / 120 秒持久冷却。

所有条件在扣除灵性前由服务端检查。非法目标、编队已满、灵性不足、冷却中或他人秘偶均不会
修改目标、名单、灵性或冷却。

## 3. 管理命令

| 命令 | 作用 |
|---|---|
| `/pm marionette` | 显示规则、槽位、已加载实体的生命与维度；收纳状态单独显示，其他未加载槽位显示 UUID |
| `/pm marionette recall` | 只召回当前已加载、同维度且仍属于自己的秘偶 |
| `/pm marionette release <1..3>` | 解除指定槽位；实体已加载时同步移除所有权 |
| `/pm marionette release all` | 清空全部槽位，并解除当前已加载的所有秘偶 |
| `/pm marionette mode <1..3> follow|guard|passive` | 修改指定槽位的持久战术；已收纳秘偶直接更新权威实体载荷 |
| `/pm marionette mode all follow|guard|passive` | 批量修改全部已加载或已收纳槽位 |

召回不会强制加载区块，也不会跨维度传送实体。服务器只在玩家周围寻找有坚实地面、位于世界
边界内且无碰撞的落点；没有安全位置时对应秘偶留在原处。

## 4. 收纳卷轴与跨维部署

### 4.1 合成与操作

- 配方：纸 ×2、灰烬丝线 ×2、记忆封蜡 ×1。
- 空卷轴不可堆叠；对自己的已加载秘偶使用，消耗 5 灵性并进入 40 tick / 2 秒物品冷却。
- 收纳目标必须仍在玩家三槽名册中、保持主人 UUID、存活、无乘客且未被另一条收纳记录占用。
- 对地面使用时以点击相邻方块为候选落点；对空中使用时以视线前方为候选落点。
- 服务器在当前玩家维度搜索世界边界内、下方表面坚实且实体包围盒无碰撞的位置，因此可从主世界收纳后在下界或末地部署。

### 4.2 权威账本与防复制

卷轴不保存可直接反序列化的实体 NBT。玩家 schema 28 的 `marionette_storage_records` 保存最多三条权威记录，每条绑定：

- 名册中的实体 UUID；
- 一次性随机 token；
- 完整服务端实体 NBT，包括类型、生命、装备、效果与持久数据。

卷轴只保存主人 UUID、实体 UUID、一次性 token 和展示用名称/类型。部署必须同时满足主人、名册和 token 精确匹配；实体 NBT 永远从服务端账本读取。成功加入世界后才撤销账本并清空卷轴，因此：

- 复制同一卷轴只能让第一张成功，后续凭证立即失效；
- 修改卷轴显示类型、名称或自行注入实体 NBT 不会改变部署实体；
- 他人拾取不能部署主人绑定卷轴；
- `/pm marionette release` 会同步撤销权威记录，使遗失卷轴永久失效；
- 无安全落点、载荷非法或世界拒绝生成时，卷轴与账本保持不变，可换位置重试；
- 若同 UUID 实体已经加载，服务端拒绝复制并撤销冲突收纳记录。

## 5. 战术、跟随与离线休眠

| 模式 | 行为 |
|---|---|
| `follow` | 与在线同维门主距离超过 8 格时跟随；协助攻击门主最近攻击或最近伤害门主的非玩家生物 |
| `guard` | 切换时锚定当前位置；只保护 12 格守卫区并攻击无主普通敌对生物，离锚点过远时返回 |
| `passive` | 清除攻击目标与寻路，不主动跟随或战斗；用于运输、展示和高风险多人场景 |

- 战术写入实体 Forge 持久 NBT；收纳时进入服务端权威载荷，部署后保持原模式。
- `follow` 协助目标必须存活、同维度且在秘偶 24 格内；`guard` 不接受玩家、玩家秘偶或有主人实体。
- 门主离线时，已加载秘偶保存原 `NoAI` 值并强制进入休眠，清除目标与导航；门主重新上线后只恢复系统写入的休眠状态，不覆盖实体原本的 NoAI 配置。
- 门主在线但跨维度时，秘偶停止跟随与门主协助，不会追踪到未加载世界；守卫模式仍遵守本地安全目标限制。
- 秘偶不能伤害任何玩家或任何玩家的秘偶；门主也不能误伤自己的秘偶。
- 外部生物仍可正常伤害秘偶；秘偶死亡后，在线门主的槽位会立即移除。

## 6. 持久化与修复

Capability schema 30 继承 schema 27–29 的编队、权威收纳与无面人字段，并继续兼容：

- `marionette_roster`：最多三个去重 UUID，保持插入顺序；
- `marionette_creation_cd_end`：创建冷却结束 tick；
- 命名 DataFix `persistent_marionette_roster`：为 schema 26 旧档建立空名单与安全冷却；
- `marionette_storage_records`：服务端权威 token 与实体载荷记录；
- 命名 DataFix `marionette_storage_records`：为 schema 27 旧档建立空收纳账本；
- 战术模式、守卫锚点和离线休眠标记保存在实体 Forge 数据中，并随权威收纳载荷跨维部署；
- 命名 DataFix `m3_squad_governance`：为 schema 29 旧档补充组织门治理字段，不改写既有秘偶载荷；
- 非法名单容器和损坏 UUID 会保留到 `orphaned_entries`，而不是静默覆盖。

秘偶实体同时保存 `lord_of_mysteries:marionette_owner`。玩家名单是授权来源，实体所有权是运行时
识别来源：已加载实体若不再存在于门主名单，会自动解除所有权，避免复制 NBT 形成额外秘偶。

## 7. 单人和多人边界

- 单人：名单、冷却、实体所有权和召回均由服务端保存；重启不会恢复灵性或冷却。
- 多人：一个实体只能有一个门主；抢夺其他玩家秘偶会无损拒绝。
- 物品复制：权威 token 仅可消费一次，背包复制、创造模式复制或 NBT 篡改都不能生成额外实体。
- 跨维：收纳后实体不留在原维度；部署总是在卷轴主人当前维度重新验证安全落点。
- PvP：秘偶对所有玩家的伤害事件直接取消，不依赖服务器 PvP 开关。
- 友军：门主不能误伤自己的秘偶；不同门主的秘偶之间也不会形成间接 PvP。
- 区块：系统不强制加载未加载区块；名单显示“未加载”不等于实体丢失。
- 离线：门主离线期间已加载秘偶强制 NoAI 休眠。若秘偶在门主离线时被其他来源杀死，旧 UUID 可能暂时留在名单，
  玩家可用 `release` 清理；当前版本不会扫描全部世界或离线玩家文件。

## 8. 失败矩阵

| 场景 | 结果 |
|---|---|
| 普通按 `U` | 执行既有提线束缚，不创建秘偶 |
| 潜行按 `U` 但目标不是敌对生物 | 拒绝，不扣灵性 |
| 目标生命高于 20% 或最大生命高于 80 | 拒绝，不扣灵性 |
| 目标是玩家、Boss 或他人秘偶 | 拒绝，不扣灵性 |
| 已有 3 个槽位 | 拒绝，不修改实体 |
| 灵性不足 60 | 拒绝，不开始冷却 |
| 创建成功 | 扣 60 灵性、写入 120 秒冷却、持久化实体与槽位 |
| 切换 `guard` | 记录当前守卫锚点，只攻击 12 格内无主普通敌对生物 |
| 切换 `passive` | 清除战斗目标与导航，不主动移动或攻击 |
| 秘偶已收纳时切换模式 | 原子更新服务端权威 `ForgeData`；卷轴不保存可伪造实体载荷 |
| 门主离线后实体仍加载 | 保存原 NoAI、清除目标/导航并休眠；门主上线后安全恢复 |
| 召回目标未加载或跨维 | 跳过，不加载区块 |
| 召回附近无安全位置 | 跳过，目标留在原处 |
| 槽位已解除但实体随后加载 | 运行时校验后自动解除所有权 |
| 用空卷轴收纳自己的已加载秘偶 | 扣 5 灵性，写入权威账本和一次性凭证，移除原实体 |
| 用卷轴收纳他人秘偶、未入册实体或有乘客实体 | 拒绝，不扣灵性、不修改实体 |
| 在另一维度找到安全落点 | 恢复同一实体 UUID、状态和所有权，并消费账本记录 |
| 复制卷轴在首次部署后再次使用 | `INVALID_TOKEN`，不生成实体 |
| 他人持有主人绑定卷轴 | `WRONG_OWNER`，不读取或改变权威载荷 |
| 无坚实无碰撞落点 | 保留卷轴与权威账本，可换位置重试 |
| `release` 后使用旧卷轴 | `RELEASED`，旧 token 永久失效 |

## 9. 自动化证据

- `MarionettePolicyTest` 覆盖捕获阈值、玩家/非敌对/他人目标拒绝、三槽上限及稳定去重。
- `PlayerMysteryDataTest`、`PlayerMysteryDataFixerTest` 与 `PlayerMysteryDataSanitizerTest` 覆盖 schema 26→27→28、深复制、NBT 往返、冷却修复、非法容器、伪造载荷和损坏 UUID 孤儿保留。
- `MarionetteStoragePolicyTest` 覆盖服务端载荷防御复制、token 精确匹配、名册约束、伪造 UUID 拒绝和读副本不可回写。
- `MarionetteTacticalModeTest` 覆盖三种模式解析、大小写兼容和损坏值安全回退。
- 第 17 项 Forge GameTest 使用真实服务端玩家与僵尸验证精确扣费、实体所有权、schema 27 NBT、
  冷却、他人抢夺拒绝和显式解除。
- 真实 Forge GameTest 验证 5 灵性收纳、schema 30 Provider 重启、他人持券拒绝、无安全落点时账本/卷轴原子保留、同 UUID 安全部署、权威记录消费与复制凭证拒绝。
- 第 22 项 Forge GameTest 验证守卫模式写入实体、跨权威收纳与部署保持同 UUID/同模式、切换被动后清除攻击目标。
- M3 机器合同检查命令入口、数值常量、玩家伤害禁令、同维安全召回、无强制区块加载及持久字段。

自动化不能替代真实玩家跨维操作、长时区块卸载、门主离线死亡、不同敌对生物 AI 和多人高延迟的真人验收。
