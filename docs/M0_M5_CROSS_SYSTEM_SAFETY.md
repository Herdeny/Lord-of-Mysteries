# M0–M5 跨系统安全、恢复与原子失败

> 适用版本：`0.9.35-1.20.1` · 设计基线：v0.9 · 当前里程碑：M6
>
> 状态：服务端权威门禁已实现；29 项 Forge GameTest 中第 29 项验证真实世界内的跨系统原子拒绝。

## 为什么需要统一门禁

共享梦境和灵界远征都保存现实返航点、独立进度、结算资格与异常恢复记录。远门、晋升仪式、净化仪式和秘偶收纳也会修改位置、物品、灵性或持久账本。若这些系统同时执行，可能出现重复结算、返航覆盖、跨维绕过、材料误扣或实体账本分叉。

`OccultActivityService` 因此把 M0–M5 的高风险入口统一为服务端权威的独占活动状态。客户端提示、维度位置与单个物品 NBT 都不能单独放行。

## 七种权威状态

| 状态 | 含义 | 安全处理 |
|---|---|---|
| ordinary world activity | 没有梦境、恢复或灵界记录 | 可开始新的独占活动 |
| shared-dream consent lobby | 已加入邀请大厅，即使尚未接受 | `/pm dream leave` |
| active shared dream | 梦境已启动、完成待退出或失败待结算 | `/pm dream exit` |
| queued shared-dream recovery | 服务端保存了逐人返航记录 | `/pm dream recover` |
| shared-dream dimension without a session | 玩家位于梦境维度但没有有效会话 | `/pm dream recover` |
| spirit-world expedition | 存在远征记录或玩家位于灵界维度 | `/pm spirit exit`；中断后用 `/pm spirit recover` |
| conflicting dream and spirit records | 两类独占证据同时存在 | 依次执行两个恢复命令；仍冲突时由管理员检查存档 |

任何时候可执行 `/pm activity`。它只读取服务端 SavedData 与当前维度，不修改物品、冷却、位置或进度。

## 入口与不变式

| 操作 | 拒绝条件 | 拒绝后必须保持不变 |
|---|---|---|
| 开始灵界远征 | 任意梦境大厅、会话、恢复或梦境维度 | 航路灯耐久、远征记录、玩家维度与位置 |
| 开启旅行家远门 | 门主处于独占状态，或目标是共享梦境/灵界维度 | 灵性、冷却、源/目标门实体 |
| 穿过已有远门 | 玩家处于独占状态，或门指向受保护维度 | 玩家位置、通行冷却、返航记录 |
| 序列 5 晋升仪式 | 梦境、灵界或待恢复状态 | 仪式证明、全部材料、压力与污染 |
| 净化封印仪式启动 | 主持人处于独占状态 | 祭坛材料、状态机与主持人记录 |
| 净化封印仪式进行中 | 在线主持人死亡、旁观、跨维、离开 12 格或进入独占状态 | 取消仪式但保留材料；短暂离线仍暂停 60 秒后才取消 |
| 秘偶收纳或部署 | 梦境、灵界或待恢复状态 | 实体、卷轴凭证、名册、收纳账本、灵性与冷却 |

普通失败必须发生在扣费、创建持久记录、生成实体或传送之前。若后续世界操作失败，既有系统仍执行退款、回滚或安全返航。

## 多人规则

- 梦境邀请大厅本身就是独占状态；待接受玩家不能利用等待期进入灵界或执行高风险系统。
- 旅行家开门只邀请当前可参与的同行者；处于梦境、灵界或恢复状态的候选人不会进入名单。
- 门主不能把远门直接指向 M5 的两个语义维度；手工构造、旧存档或命令生成的门在实际通行时还会再次拒绝。
- 每个玩家按 UUID 独立检查。一个队员的恢复状态不会修改其他人的账本，也不会让门主替其确认同意。

## 管理员排障

1. 让玩家执行 `/pm activity`，记录状态文本。
2. 梦境大厅使用 `/pm dream leave`；梦境会话使用 `/pm dream exit`；孤立或待恢复状态使用 `/pm dream recover`。
3. 灵界正常远征使用 `/pm spirit exit`；无记录、错维或重启中断使用 `/pm spirit recover`。
4. 再执行 `/pm activity`，必须回到 ordinary world activity 后才能重试仪式、远门或秘偶操作。
5. 若显示 conflicting dream and spirit records，不要删除整个玩家数据。先保留世界备份，再分别检查 `lord_of_mysteries_shared_dreams` 与 `lord_of_mysteries_spirit_expeditions` SavedData。
6. 使用 `/pm doctor` 和 `/pm servercheck` 检查定义、协议、目标维度与迁移状态；处理后执行保存、停服、重启和二次诊断。

## 自动化证据

- 10 项 `OccultActivityPolicyTest` 穷举普通、大厅、活动、恢复、孤立维度、灵界记录与双记录冲突。
- `RitualRecoveryLogicTest` 同时覆盖在线合格继续、在线失格立即取消、短暂离线暂停、超时取消与非活动忽略。
- 第 29 项 Forge GameTest 在真实专服维度中验证：梦境大厅拒绝灵界进入、序列 5 仪式、普通远门和秘偶收纳；关闭大厅后仍拒绝伪造的梦境目标远门。
- 断言检查航路记录、灯耐久、维度、仪式证明、材料、秘偶实体、卷轴、账本、灵性与冷却均未发生非预期变化。
- M5 机器合同会校验统一策略类、玩家诊断命令、受保护维度、仪式主持人资格与秘偶冲突分支没有从代码中漂移。

## 仍需真人验证

自动化不能替代 2–4 人真实网络延迟下的提示可读性、恢复命令易用性和 30 分钟连续体验。真人验收应主动覆盖：邀请期间断线、投票中换队、远征中重连、门前切换状态、主持人离开祭坛边界、背包满与服务器重启。发现问题时记录世界种子、玩家 UUID、命令顺序、游戏时间和服务端日志，不以“测试数量增加”替代复现证据。
